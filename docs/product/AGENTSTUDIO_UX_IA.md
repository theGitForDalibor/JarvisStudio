## 1. 架构重塑理念：从“Chat 调试器”走向“个人 Agent 工作空间”

### 1.1 现状交互模式诊断与痛点
现有 Jarvis Studio 前端（`api/static/index.html`）采用的是“**Chat 单屏 + 开发者调试 Tab**”架构：
- **痛点 1（任务与成果被严重湮没）**：用户必须在长达数十页的聊天历史中向上滚动寻找两小时前生成的方案或代码，极易遗失；
- **痛点 2（技术认知过载）**：主导航为“对话、审批、记忆、知识库、Traces、系统”，普通用户直接面对毫秒级 TTFT 统计卡片和 JSON Payload，缺乏以“我当前有哪些目标、产出了什么成果”为中心的组织结构；
- **痛点 3（生命周期不可见）**：底层已具备完整的 `agent_tasks`（10态）和 `agent_runs`（7态），前端却只能展示转圈动画或硬编码的“正在理解您的指令...”，无法掌控执行全貌。

### 1.2 AgentStudio 全新信息架构原则
1. **双轨工作空间 (Dual-Track Synergy)**：Chat（即时、探索、发散）与 Task（持久、结构化、交付物）并存，并可一键相互转化。
2. **渐进式暴露 (Progressive Disclosure)**：首屏默认展现“结果与交付物（Result & Deliverables）”，次层展现“执行时间线与工具调用（Timeline & Tools）”，深层折叠展现“技术底层跟踪（Trace & JSON）”。
3. **拒绝虚假思考，强化真实控制**：去除一切假进度条与伪思考文本，以真实的节点跃迁、工具 I/O 和流式 Token 为时间线更新源；随时提供暂停、改参和取消入口。

### 2.1 候选模块独立性与收敛分析

| 候选模块 | 判定结果 | 布局归宿 | 决策理由与交互定位 |
| :--- | :---: | :--- | :--- |
| **Dashboard** | **独立一级模块** | 顶部主导航首项 | 用户的“每日工作台”。呈现全局行动呼吁（Call-to-Action）：在跑任务、待审批阻塞项、最新交付物。拒绝无意义的统计图表大屏。 |
| **Task Center / Detail** | **独立一级核心** | 顶部主导航次项 | **AgentStudio 的灵魂所在**。管理所有持久化任务，沉淀最终交付成果。 |

| **Agent Center** | **独立一级模块** | 顶部主导航第四项 | 契合产品定位中的“Create, Configure, Orchestrate AI Agents”，支持用户自定义专属 Agent。 |
| **Knowledge Base** | **资源类二级模块** | 侧边栏/主导航收纳 | 属于“数据与资源支撑层”，提供文档入库状态监控与向量检索测试。 |

#### 关键交互机制
1. **Result & Deliverables 首屏优先**：
   - 任务完成后，左侧默认展开正式交付物（Markdown、HTML 报告、代码 Diff 或数据表）。
   - 提供 Markdown 代码块一键复制、Mermaid 架构图实时渲染、导出 HTML/PDF 按钮。
2. **渐进可观测时间线 (Execution Timeline)**：
   - 右侧仅展现**真实执行节点**：Agent 委托、工具调用（名称、实参简写、耗时、状态）、HITL 审批节点。
   - 工具卡片可点击展开查看完整的 Input JSON 与 Output Summary。
3. **Run 历史版本抽屉**：
   - 展现该 Task 经历的所有物理 Run（如 Run #1 挂起审批，Run #2 审批通过后完成）。
   - 用户可回溯查看每轮 Run 对应的事件切片。
4. **技术 Trace 下沉隔离**：
   - 在右侧抽屉底部保留“底层 Trace (White-box Debug)”入口，点击展开包含 TTFT、TTFA、Token 计量与 Raw Checkpoint ID 的高级诊断面板，不打扰非技术用户。

### 3.2 核心视图 B：对话工作台 (Chat Arena) — 探索与任务孵化器

Chat 保持轻量与灵敏，同时与 Task 深度协同。

│ │ • API 对接   │ │ │ 💡 建议立项为 Task: [2026 本地向量库性能比对与调研]           │ │ │

│ │              │ │ └──────────────────────────────────────────────────────────────┘ │ │

#### 关键交互点
1. **意图转化为 Task (Convert to Task)**：
   - 用户可在任意一条助理回复气泡旁点击“📍 立项为 Task”，系统自动提炼目标并跳转至 Task 配置弹窗；
   - 助理也可主动识别复杂任务，在气泡中输出“一键立项卡片”。
2. **实时任务进度气泡 (In-Chat Task Pill)**：
   - 任务在后台异步执行时，对话窗口保留轻量级状态药丸（Pill），显示当前正在调用的工具或是否等待审批。
3. **跨模式上下文继承**：
   - 从 Chat 孵化的 Task，自动将当前 Session 中近 3 轮关键讨论作为 `context_brief` 写入 Task，保证 Agent 理解前因后果，无需用户重敲背景。

### 3.4 核心视图 D：智能体中心 (Agent Center) — 配置与编排

用户在此查看系统内置的专业 Agent，并根据需要克隆或创建自定义 Agent。

1. **Agent 列表卡片**：
   - 展示 Agent 图标、名称、职责描述、绑定模型（如 gpt-4o, deepseek-chat）、已挂载工具数、系统保护标签（Built-in vs Custom）。
2. **系统保护机制**：
   - 内置 Agent（General Agent, Research Specialist 等）标注锁定徽标，核心保护配置不可篡改；
   - 提供“创建副本 (Duplicate / Fork)”功能，用户可基于内置 Agent 模板一键派生属于自己的自定义 Agent。
3. **配置抽屉 (Agent Drawer)**：
   - **基础属性**：名称、角色定义 (Role Description)、系统提示词 (System Prompt)；
   - **模型选择**：选择默认 Provider 与 Model，调整 Temperature；
   - **工具挂载**：分类勾选允许调用的工具（文件工具、Shell 工具、RAG 检索、指定 MCP 工具）；
   - **权限策略**：配置该 Agent 调用各工具时的安全级别（默认继承系统规则或强制触发审批）。

## 4. 关键人机协作交互状态规范 (HITL UX)

### 4.1 操作审批卡片规范 (Operation Approval Card)
当命中高危工具拦截时，系统不仅在 Task Timeline 插入阻断节点，同时在全局顶部通知栏提示。
审批弹窗/内嵌卡片包含：
1. **工具标识与风险标度**：显式展示 `[HIGH RISK]` 红标签、工具名称（如 `execute_shell_command`）。
2. **操作意图摘要**：大白话解释 Agent 试图执行的目的（如“Agent 正在尝试执行命令：`pytest tests/`”）。
3. **参数强校验编辑器**：
   - 默认以语法高亮展示格式化的 JSON 参数；
   - **支持原位编辑 (In-place Edit)**：用户可直接修改输入框中的参数（例如将删除路径改为备份路径），点击“改参后执行 (Modify & Resume)”，后端无缝应用修改后参数。
4. **决策三选一**：
   - `[ 批准执行 (Approve) ]`：绿色按钮，立即恢复物理执行；
   - `[ 改参执行 (Modify) ]`：橙色按钮，校验 JSON 无误后带参恢复；
   - `[ 拒绝此步 (Reject) ]`：红色按钮，支持可选输入拒绝理由，Agent 收到拒绝信号后自行调整下一步规划。

### 4.2 计划确认交互规范 (Plan Review)
与操作审批不同，计划确认面向任务逻辑：
- 复杂任务生成结构化步骤清单（Step 1: 搜索背景资料 -> Step 2: 提取对比矩阵 -> Step 3: 撰写报告）；
- 用户可选择：
  - `[ 确认执行 ]`：Agent 依照计划逐步推进；
  - `[ 调整计划 ]`：用户在步骤列表上直接删除某步或拖拽调整顺序，确认后执行；
  - `[ 跳过确认 ]`：在设置中可配置中低复杂度任务免除计划弹窗。

## 5. 前端技术栈与工程实现演进路线

现有 `index.html`（1769 行单文件原生 JS）已达到维护极限，难以支撑 Task Center 与 Deliverable 渲染的双轨需求。

### 5.1 前端演进选型决策
- **选型原则**：极简工程流、零臃肿 Node 构建黑盒、单机启动即用、完美契合 FastAPI 静态托管。
- **推荐方案**：采用 **现代轻量 ESM 组件化单页应用**（或 Vue 3 / Preact + Tailwind CSS via CDN / 极轻量 Vite 构建）：
  - 核心 Markdown 渲染：继续复用并加固 `marked.js` + `highlight.js`，引入 `mermaid.js` 流程图渲染；
  - 状态管理：轻量 Reactive Store，维护活跃 Task 状态与 SSE 长连接；
  - SSE 通信管道：建立统一的 `TaskEventSource`，分发 `token`, `tool_start`, `tool_end`, `status_change`, `deliverable_ready` 事件，驱动时间线无闪烁动态增量更新。
